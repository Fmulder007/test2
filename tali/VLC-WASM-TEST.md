# Тест VLC WebAssembly для TALI

Отдельная диагностическая страница. Основной `index.html`, `app.js`, `style.css`, API и базу данных TALI не меняет.

## Состав

- `vlc-wasm-test/index.html`, `app.js`, `style.css` — тестовая страница и управление.
- `vlc-wasm-test/nginx-vlc-wasm-test.conf` — отдельный location с COOP/COEP.
- Библиотека libvlc-wasm 0.2.0 загружается с jsDelivr CDN. Сборку на домашнем сервере делать не требуется.
- Для слабого Atom ограничены потоки VLC: 2 рабочих потока, 1 поток декодера, кеш HTTP 8 MiB, шрифты субтитров отключены на первом этапе.

## Установка на TALI

1. Перед изменениями сделать свежий ZFS snapshot TALI.
2. Скопировать каталог `vlc-wasm-test` в `/usr/local/www/tali/vlc-wasm-test/`.
3. В существующий `server { ... }` блок Nginx TALI добавить содержимое `nginx-vlc-wasm-test.conf`. Это отдельный URL location; глобальные заголовки и другие location не менять.
4. Проверить конфигурацию: `jexec tali nginx -t`.
5. Только если проверка успешна, перечитать Nginx: `jexec tali service nginx reload`.

## Проверка

Обычный HTTP по адресу `192.168.2.222` браузер считает небезопасным контекстом. Для SharedArrayBuffer нужны одновременно secure context и COOP/COEP. Поэтому без HTTPS обычный запуск по IP не пройдёт.

Если пока принципиально не включать HTTPS, для разового теста в Chrome на Windows можно запустить отдельный экземпляр с тестовым флагом (не использовать такой режим для повседневного браузинга):

```bat
chrome.exe --user-data-dir="C:\\Chrome-VLC-WASM-Test" --unsafely-treat-insecure-origin-as-secure=http://192.168.2.222
```

После запуска этого окна открыть:

`http://192.168.2.222/vlc-wasm-test/`

Флаг делает указанный HTTP-origin доверенным только в этом тестовом профиле; COOP/COEP в Nginx всё равно обязательны.

В поле адреса указать путь к существующему файлу из видеотеки, например:

`/video/Каталог/Фильм.mkv`

Страница сама проверит `crossOriginIsolated` и наличие `SharedArrayBuffer`. Затем загрузит libvlc-wasm и откроет указанный URL. Видео запрашивается напрямую у Nginx TALI, а не через API и не через VLC-сервер на порту 8090.

Для URL-воспроизведения libvlc-wasm использует HTTP Range-запросы. Проверка перемотки является частью этого эксперимента.

## Важно

- Не добавлять COOP/COEP глобально для всего сайта: заголовки включены только для `/vlc-wasm-test/`.
- Страница не запускает и не меняет системный VLC, Telnet 4212 или HTTP-поток 8090.
- На первом этапе не подключены плейлисты, профили, история и API TALI.
- Интернет-доступ браузера к jsDelivr нужен для загрузки библиотеки и WASM-файла.
